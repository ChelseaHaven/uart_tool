# UART Tool · 串口调试

基于现有 Qt Quick 工程的串口接收工具，支持亮色与暗色中文界面。C++ 使用 QSerialPort 异步收发，QML 显示文本和 HEX。支持原始监视、数字文本（CSV）、键值文本（字典）和可配置二进制协议解析；提供可拖入的实时数值时序图；支持文本／HEX 发送及解析数据 CSV 录制。

## 在 VS Code 中运行

1. 打开本工程文件夹 `/home/kwille/my_work/qt_project/uart_tool`。
2. 使用现有 **Qt C++ Extension Pack、CMake Tools、C/C++** 扩展。
3. 提示选择配置预设时选 **Qt 6.12 · 串口接收 · Debug**。
4. 按 **F5**，选择 **串口接收工具 · F5**。它会自动配置、编译、启动；Ctrl+F5 可不调试运行。
5. 使用 CMake Tools 时也可以依次执行 **CMake: Configure → CMake: Build → CMake: Run Without Debugging**，运行目标选 `appuart_tool`。

新配置使用 `build` 目录，旧的 `builds` 不再使用，无需手动删除。原有 Qt 插件调试配置仍然保留。

终端一键运行：

```bash
cd /home/kwille/my_work/qt_project/uart_tool
./run.sh
```

项目预设沿用本机 Qt 6.12.0、CMake、Ninja 路径。迁移机器时调整 CMakePresets.json、.vscode 配置和 run.sh。Windows 上可直接使用 Qt Creator 打开 CMakeLists.txt，选择有 SerialPort 的桌面 Qt Kit，并使用单独的构建目录。

在同时提供 X11 兼容显示的 Linux Wayland 会话中，默认先尝试 `xcb`，不可用时回退到 Wayland。也可以显式设置 `QT_QPA_PLATFORM=wayland` 使用原生 Wayland，或设置 `offscreen` 做无窗口检查。

## 操作

- 插入设备后点击 **刷新**，选择正确端口；列表显示系统枚举的全部串口及设备描述，包含 USB、板载 COM、ttyS 和蓝牙等端口，不再做 USB 筛选。
- 默认 **115200、8N1、无流控**；波特率可直接输入正整数，最终是否支持由系统驱动决定。
- 数据位支持 5～8；校验支持无、偶、奇、Space、Mark；停止位支持 1、2；流控支持无、RTS/CTS、XON/XOFF。
- 点击 **连接串口** 后开始接收，连接期间串口参数锁定。断开后重新连接开始新的接收会话，清除旧数据和计数；仅断开会保留历史内容。
- **文本** 使用 UTF-8，分批到达的完整中文字符可以正确重组；尚不完整的尾部字符等待后续字节再显示。非法 UTF-8 以替代符显示，控制字节以可见符号显示，建议二进制数据使用 HEX。
- 文本将 CRLF 和 CR 统一为换行；HEX 不改变原始字节，使用大写十六进制、空格分隔，每行 16 字节。显示行不是协议帧。
- 文本和 HEX 可随时切换，对同一份保留的原始缓存重新格式化。用鼠标拖选后，可按 Ctrl+C 或右键复制。
- 原始数据默认显示本机收发时间 `HH:mm:ss.ffffff`。文本行使用行首字节的读取时间，接收 HEX 按读取批次显示，同批的多行共用时间。发送记录使用提交到串口队列的时间。可用「时间戳」开关切换。
- 日志中 RX 为青色，TX 为琥珀色。底部可分别勾选接收和发送记录，切换筛选会保留历史。接收计数和协议解析只使用 RX。
- **暂停显示** 只冻结画面，接收和累计字节数继续更新。暂停期间切换模式会在恢复显示时生效。
- **清空** 同时清除原始缓存、显示和接收计数，即使暂停也立即生效；不会清除错误提示或改变连接状态。
- 关闭 **自动滚动** 可以向上查看历史；恢复自动滚动后回到最新数据。

## 缓存与响应

- 收发记录共享 **256 KiB** 的原始历史，超过后丢弃最早的数据，并显示黄色提示。
- 显示文本上限为 **262144 个字符**。HEX 由于每个字节占多个显示字符，只能显示原始缓存中最近约 85 KiB 的内容，也会提示上限。
- 累计接收计数不受缓存截断影响，直到清空或成功开始新连接。
- QSerialPort 读取缓冲上限为 64 KiB；UI 每约 50 ms 合并更新。显示采用增量插入／裁剪，尽量保持文本选择及滚动位置。
- `ReceiveBuffer` 管理原始历史，`ByteFormatter` 负责文本／HEX 格式化，`ReceiveSession` 管理计数与显示。`ByteSource::bytesReceived`（或会话转发的 `rawBytesReceived`）提供字节块，后续解析器可增量消费，不能将一次信号视为一帧。

## 打不开端口时

- 关闭可能占用设备的串口工具，如 VOFA、串口监视器；点击刷新，确认设备仍存在。
- 检查接收端和设备的波特率、数据位、校验位、停止位是否一致。
- Linux 可以用 `ls -l /dev/ttyACM0`（换成实际路径）查看所属用户组，再用 `id -nG` 检查自己的组。无权限时按本机管理方式配置设备访问组或 udev 规则，修改组后通常需重新登录。
- 程序不修改设备权限、不执行 sudo，也不会自动重连。拔出设备后会断开并显示错误，插回后刷新并手动连接。
- 列表中的 ttyS* 可能是系统枚举的板载串口，并不代表连接了 USB 设备；应根据设备描述选择真实端口。

## 分层结构

当前实现已拆分为核心数据、串口接入、接收会话、界面适配与 QML 组件。详细职责、数据流、生命周期和 ROS 扩展约定见 [docs/architecture.md](docs/architecture.md)。

- `src/core`：字节源接口、原始缓存和显示格式化。
- `src/sources/serial`：串口设备与参数、枚举和异步读取。
- `src/application`：通用接收会话及本程序服务装配。
- `src/presentation`：串口配置的 QML 适配。
- `qml`：窗口、连接面板、接收面板和公共控件。

原来的根目录 `SerialController` 已拆除，`Main.qml` 移入 `qml`。运行目标仍为 `appuart_tool`，F5 和 `./run.sh` 使用方式不变。新增的 `receive_core_tests` 是纯 Qt Core 验证程序，无需串口设备或图形界面；串口与 QML 集成测试仍为 `receiver_tests`。

## 组件与时序图

主页面默认从左至右为 **连接／组件菜单、组件工作区、数据接收** 三列；连接侧栏宽度固定，中间工作区约占其余宽度的 56%，接收区约占 44%。三个面板均可拖出浮动或吸附。接收区的暂停显示和清空位于页签右侧。左侧仍切换 **连接／组件**，把 **时序图** 拖入组件工作区，在松手处按组件左上角生成（滚动画布及浮动工作区同样支持），再点击图内 **选择参数** 勾选曲线。每张图最多 8 条曲线，点击 × 删除。

组件工作区是自由画布：拖动图表标题移动，拖动四边或四角拉伸，双击标题或点击 □ 最大化／还原；超出工作区的部分可通过滚动条查看。面板之间的分隔条可拖动调整大小。

组件工作区提供「导入布局」和「导出布局」，可用 JSON 文件分享组件类型、位置、大小和快捷发送配置。正常关闭时保存当前布局，下次启动自动恢复。首次启动且没有保存记录时画布为空。图表字段重新选择，快捷发送保留发送草稿、字典参数、步长和发送设置，恢复时不会自动发送。

图表的交互方式：

- 在绘图区滚动鼠标滚轮，同时缩放横轴与纵轴，以鼠标位置为中心。
- 在底部横轴或左侧纵轴滚动，只缩放对应坐标轴。
- 按住鼠标拖动绘图区平移；拖动坐标轴只平移对应轴。
- 手动调整后保留当前视野，点击 **自动** 或双击图内恢复实时跟随和自动量程。
- 默认显示最近 10 秒，时间轴可缩放至 1 毫秒～60 秒；可查看的实际历史还受采样率及每通道缓存点数限制。

参数仅来自当前协议实际解析成功的数值：CSV 的 CH1、CH2 等、键值文本中的名称、二进制标量和数值数组元素（例如 samples[0]）。未解析出参数时列表为空。 字典协议按字段名独立更新。某行缺少的字段保留上次显示值和曲线历史，只为该行实际收到的字段添加采样点。切换接收页签时曲线继续更新，更换协议、命令或清空接收时会同步清空图表数据和参数。曲线默认显示最近 10 秒，纵轴自动缩放，接收区的暂停显示会同时冻结曲线，恢复时显示最近缓存。不同量纲可分配到不同图表。

数值通道与控件独立，每次成功解析的帧都会采集，界面约 50 ms 刷新；最多 128 个数值通道，每通道最多 8192 个点并限制在最近 60 秒，组件区最多 8 张图。使用 Qt Quick 自绘，不依赖 Qt Charts。组件布局和选中参数本版不持久化。

## 面板浮动与吸附

“协议与连接／组件菜单”、“组件工作区”和“数据接收”均通过拖动顶部手柄拉出独立窗口。停靠和浮动共用一条标题栏，浮动后直接拖动最上面的标题栏即可拖回；右侧保留最小化、最大化／还原、关闭吸附按钮，窗口边缘支持缩放。拉出前设置好窗口位置，浮动窗口通过从属关系保持在主窗口之上，避免重复显示和置顶，不再提供浮动按钮。贴靠分为主工作区“大框”和内部面板“小框”：主工作区外沿选择全局目标，内部选择鼠标所在的已停靠面板；只有靠近目标边缘的中点小范围时，才出现相应方向的标识和预览边框；沿边缘其他位置或靠近角落不会触发。预览只画边框，不填色，不插入空位、不改变当前布局；松手后才沿对应方向对半分目标区域（中间保留分隔条）。内部面板吸附只调整目标区域，其他面板的方位保留。

连接／组件菜单为固定宽度侧栏：可以拖出，浮动后尺寸固定，不显示最大化及缩放手柄；放回仅允许主工作区左侧或右侧。侧栏始终独占整列，其他面板在其余区域贴靠。拖动侧栏分隔条向窗口外侧超过一小段距离，会直接折叠成窄边；从窄边向内拖动即可恢复固定宽度，也可点击窄边展开。左右停靠时方向自动对应，不进行连续宽度拉伸。

其他面板拉出后由剩余可伸展面板铺满可用区域，没有临时或常驻空位。浮动面板再次拖动时，现有布局也保持不变。预览在主窗口内部绘制，拖动中的浮动面板略微透明，松手恢复。关闭浮动窗口会返回当前布局。三个面板都浮动时，主窗口仍提供 **全部吸附**。停靠时拖动分隔条调整尺寸；数据接收区宽度最小为 380 逻辑像素，保证工具栏完整显示且不出现横向滚动条；高度最小可收至只剩标题栏，拉大即可恢复内容，收起时仍继续接收。

浮动和吸附移动的是同一套控件，不重建接收会话；连接、协议、日志和计数继续保留。亮暗模式同步到浮动窗口。设置页打开时暂时隐藏浮动窗口，返回接收后恢复；关闭主窗口会一并关闭浮动窗口。启动时默认三个面板均停靠。

## 原始数据与协议解析

接收区提供「原始数据」和「数据协议」两个页签。原始数据支持文本／HEX 和自动滚动。数据协议可选数字文本（CSV）、键值文本（字典）和自定义二进制。二进制的「编辑协议」按钮可配置帧头、长度、字段、字节序和校验。 单击「自定义二进制」可继续使用当前配置，悬停可展开子菜单并切换内置或个人 JSON 模板。应用后，协议框显示模板名，包含命令字时右侧显示接收命令菜单。单组模板直接列出命令，多组模板可悬停在各组上展开子菜单。

两个页签共用暂停和清空，原始日志和解析值都支持鼠标拖选后复制。切换页签时，串口接收、日志缓存、已选协议和图表继续运行。更换协议或保存当前二进制布局会清空解析状态，原始日志保留。启动默认显示原始数据，协议需手动选择。

完整说明、限制和可直接发送的示例见 [docs/protocols.md](docs/protocols.md)。模块结构见 [docs/architecture.md](docs/architecture.md)。

键值文本直接发送 `awa:2.0,  aaa:3\n`（`\n` 为真实换行），字段名无需引号，名称和数值两侧的空格自动去掉。每行解析成一组，与二进制解析一样用字段卡片显示名称和数值。

## 协议编辑与模板

“编辑协议”现在是统一页面：顶部选择已有模板，或点击“新建”从头配置，下面按发送顺序编辑帧结构。新建后填写名称并点击“保存模板”，才会生成模板文件。数据区与帧头、长度、命令字、校验和帧尾一样，通过“添加模块”添加，可删除和移动；在数据区内直接增删字段、选择类型、数量和字节序。命令字和数据区可以重复添加，例如“帧头 → 命令字 → 数据区 → 命令字 → 数据区 → 校验”。位置、偏移和帧长自动计算；数据里需要跳过字节时添加“保留字节”，只有特殊校验的覆盖范围需要手填起止位置。

每个数据区归属于前面最近的命令字；各处命令字的下拉框独立选择，该组数据区随之显示对应字段，切换时保留草稿；点击“添加命令”设置新命令值和名称。同一个模板保存全部命令。接收页选择要处理的命令；多处命令字各有独立下拉框，整帧须匹配所选命令组合，其他命令跳过，不在后台更新结果；切换接收命令会清空旧结果和解析计数，从新收到的数据开始。

模板分为“内置模板”和“我的模板”。内置模板包含简单固定帧、简单变长帧和多段命令帧，随软件打包，不可覆盖或删除；保存时创建个人副本。新建、导入和基于内置模板保存的都放进“我的模板”，以独立 JSON 文件保存，支持重命名、导入、导出和删除。个人模板目录显示在编辑器中；删除后重启不会恢复。旧版本修改过的模板保留为个人模板，网球机器人协议也属于个人模板。保存文件不改变当前接收，“应用并关闭”才更新解析器。有未保存的模板修改时会提示，可选择保存并应用或返回编辑；未修改或已经保存时直接应用。

针对 `robotmaster_c_tennis`，可在“我的模板”中选择已有的“网球机器人上行 · A5”，串口参数使用 460800、8N1。该模板和其他协议使用同一套通用规则。

多段结构中，整帧仍只需一个长度字段，放在第一个数据区前。长度表示数据区字节数时，从第一个数据区起算，包含中间的命令字和其他模块；末尾校验是否计入仍由开关决定。前面各组命令的数据字节数须相同，变长数组仅放在最后一个数据区末尾。

现支持固定帧与长度字段决定的变长帧；要求帧头，暂不支持字节转义、脚本算法和仅帧尾分隔的组帧方式。详细规则、模板格式和扩展约定见 [docs/protocols.md](docs/protocols.md)。


## 串口发送

从左侧「组件」菜单将「快捷发送」拖到组件工作区，即可使用当前连接的串口发送。卡片可选文本、HEX、字典三种格式，默认文本。文本按 UTF-8 编码。HEX 可以输入 `AA 01 FF` 或 `AA01FF`，非法字符或半个字节会报错。字典按参数顺序生成 `kp:1.2,ki:0.05`，冒号和逗号由卡片补上。结尾可选无结尾、LF、CRLF、CR，默认 LF。

点击「发送」或按 Ctrl+Enter 提交。勾选「定时发送」并设置毫秒间隔后，点击「发送」立即发送一次并开始重复发送，再点击「停止」结束。切换格式或断开串口也会结束当前定时发送。接收协议可独立选择。

单次发送最多 64 KiB（含所选结尾），串口待写队列最多 256 KiB，队列满时提示稍后再试。界面“已提交”表示字节已交给异步串口写队列，不代表设备返回了确认。暂停接收显示或折叠面板不会关闭串口。


## 串口录制

连接串口并选定协议后，点击顶栏「开始录制」，选择保存目录。每次录制创建一个按开始时间命名的子目录，例如 20261118_183005。首份 CSV 与目录同名，新增字段时才另存 20261118_183005_002.csv 等分段。

每个有效解析帧占一行，前三列为 UTC 接收解析时间 `timestamp_utc`、录制起始后经过的微秒数 `elapsed_us`、连续帧号 `frame`。参数列以 `data.` 开头，数值数组以 JSON 数组保存在一个单元格中。空缺参数留空，同一协议中若出现新参数，会开新文件并保留已知列。CSV 使用带 BOM 的 UTF-8，Python 可用 `csv.DictReader(open(path, encoding="utf-8-sig", newline=""))` 读取，Excel 导入时选择 UTF-8 和逗号分隔。

切页、暂停显示、清空画面都可继续录制。切换协议类型、应用不同的二进制模板或解析配置、切换命令字、断开串口和退出时，软件会结束录制并写完切换前已入队的帧。顶栏会保留停止原因和保存目录。CSV 仅记录从 RX 成功解析出的数值，不包含 TX 或原始字节。
